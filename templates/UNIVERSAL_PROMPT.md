# Universal prompt for a new HiMCM problem

Use the attached `himcm-o-paper` skill. Read `SKILL.md` completely before acting, then load only the linked references needed for the current stage.

Build the strongest defensible, Outstanding-ready HiMCM solution from the complete contents of `problem_files/`. Do not merely describe a plan: inspect the files, execute the modeling work, verify the evidence, write the paper, compile it, inspect the rendered PDF, and deliver a final handoff.

Operating requirements:

1. Inventory and hash every supplied file. Extract text/tables and visually inspect diagrams/images. Record unreadable content; never guess.
2. Identify the contest year and verify that year's official rules and permitted-use/AI requirements from primary or archived official sources. Do not inherit another year's page limit or policy.
3. For a historical problem, enforce the contest-time source cutoff. Disclose prior exposure to published solutions and do not present a contaminated run as blind.
4. Create `contest_profile.json`, `input_manifest.json`, and `problem_analysis.json` before modeling. Map every prompt clause to a decision contract, completion rule, and evidence location.
5. Generate and compare plausible model architectures based on the decision structure. Declare selection criteria before seeing preferred results. Choose the simplest adequate architecture; negative or non-identifiable conclusions are allowed.
6. Create a model card for every active component. Register assumptions, parameter provenance, system boundaries, units, interfaces, failure modes, validation, uncertainty, and fallback conclusions.
7. Keep raw data immutable and record every transformation. Use authoritative sources matched in definition, population, place, and time. Never fabricate or silently impute.
8. Put problem code inside the project. Add synthetic tests, run the model, preserve commands/environment/seeds/solver status/hashes, and write machine-readable result contracts.
9. Validate each claim with methods suited to its model family. Include independent recomputation, boundary behavior, conservation/feasibility, cross-artifact comparison, and external validation where possible. Sensitivity alone is not validation.
10. Treat all substitutions as first-class decisions. Do not confuse counts with weighted sums, non-significance with equivalence, transient rates with capacity, capped statistics with bounds, feasible solutions with optima, or proxies with causal/safety/fairness facts.
11. Freeze current model identities and results before prose. Maintain a claim ledger from results to Summary Sheet, tables/figures, conclusion, recommendation, and requested stakeholder deliverables.
12. Generate model numbers/tables/figures from results; do not retype them. Verify integer and decimal values, relation words, quantifiers, plot coordinates/scales, and artifact freshness.
13. Author only in LaTeX and compile directly to PDF. Do not create, require, convert, or deliver DOCX/Word files.
14. Audit the actual prompt, code, data, results, source, and PDF. Fix the earliest cause, regenerate all descendants, mutation-test new gates, and audit every repair.
15. Render and visually inspect every PDF page. A passing source/build check is not proof of a correct deliverable.
16. Continue autonomously through safe in-scope work. Ask only when a missing choice materially changes the model or requires new authority.

Required deliverables:

- contest and input manifests;
- complete requirement/decision contracts;
- model selection record and model cards;
- source/data/parameter ledger;
- executable code, tests, and run manifest;
- machine-readable results and claim ledger;
- generated tables and figures with provenance;
- complete English LaTeX source and submission PDF;
- verification, uncertainty, readiness, and PDF-render reports;
- final handoff with direct answers, model identities, key results, validation, reproduction command, rule/render status, limitations, and blockers.

Do not promise an award. Do not stop at a passing checklist. Finish only when the completion contract in `SKILL.md` is satisfied or report the exact blocker.
